## まず、自分の問いをつくる

AIを開く前に、困っていることを一文で書きます。
「誰が困るか」「何が変わればよいか」「どう確かめるか」を決めます。

```flow
困りごと → 自分の仮説 → AIで試す → 結果を確かめる
```

例：勉強が進まない。今日は一つの説明を読んで、見ずに説明できるか試す。

```quiz
Q: 勉強にAIを使う前に決めるとよいことは？
1: AIの回答の長さだけ
2: 解決したい困りごとと確かめ方
3: AIの答えを必ず採用すること
4: 難しい言葉を増やすこと
C: 2
E: 目的と確かめ方があると、回答が役立ったか自分で判断できます。
```

## 答えを受け取ったら、確かめる

AIの答えには、根拠・前提・別の見方を尋ねます。数字や制度などの事実は元の資料で確かめます。確認できなければ未確認と残します。

```flow
AIの提案 → 根拠と前提 → 元資料の確認 → 自分の判断
```

```quiz
Q: AIの答えの根拠が見つからないときは？
1: 自信のある文章なので事実とする
2: 同じ答えを繰り返させれば証明になる
3: 未確認と記録し、確認方法を探す
4: 自分に都合がよければ採用する
C: 3
E: もっともらしさと正しさは別です。分からない部分を分けることが判断を助けます。
```

## 今日の小さな実験

「今日の一歩」で一つだけ行動を選び、実行後の成果欄に次の形で記録します。個人の記録は公開リポジトリに書かず、ログイン後の記録欄を使います。

- 問い：何に困った？
- 自分の仮説：何が原因だと思った？
- AIの提案：何を試した？
- 結果：何が変わった？
- 判断：続ける・変える・やめる、その理由は？

```flow
小さく試す → 変化を記録 → 続け方を決める
```

例：説明を読むだけだった学習を、見ずに説明する練習へ変える。実際に説明できた点と詰まった点を残す。

```quiz
Q: 実績として残すと役立つものは？
1: 試したことと、実際に起きた変化
2: 使ったAIの名前だけ
3: 読まずに保存した長い回答
4: まだ起きていない成果
C: 1
E: 行動と結果を結びつけると、次の改善に使える記録になります。
```
