# デジタル経済 11講 ― 共有経済：持たずに使う、みんなで作る

**物の所有者を変えなくても、使い方を変えれば役に立つ時間を増やせます。** もう1つの柱は、みんなでソフトなどを作り、共有することです。

添付の講義ノートをもとにした教材です。日常の例や図は、理解を助ける補足です。

## 1. 共有は、無料であげることだけではない

普段は自分が持つ物でも、使わない時間に誰かへ貸せます。部屋や車の所有権を移さず、一定の時間だけ使ってもらう取引です。

```flow
使われていない時間 → 使いたい人とつながる → 役に立つ時間が増える
```

**共有経済（シェアリングエコノミー）** という言葉の範囲は、論者によって違います。現代のサービスには、有料の貸し借りも多く含まれます。みんなの物になったから、無料で誰でも使える、という意味ではありません。

同じ部屋を同じ時間に使える人数には限りがあり、払わない人の利用を制限できる場合もあります。

```quiz
Q: 共有サービスの部屋は、必ず無料の公共財？
1: 有料で、利用できる人数にも制限がありうる
2: 誰でも同時に無制限で使える
3: 使う人全員へ所有権が移る
4: 料金を取るサービスは存在しない
C: 1
E: 所有と利用の権利を区別します。共有という名前でも、利用時間を有料で割り当てるサービスがあります。
```

## 2. アプリがなくても貸せるのに、なぜ使う？

知らない相手を探し、空き時間を合わせ、料金を決め、支払いと評判を確認する。その手間を減らすのがプラットフォームの役割です。

```flow
貸す人と借りる人 → 検索・評価・料金・支払い → 取引しやすくなる
```

提供する部屋や車を、仲介会社自身が持っていない場合もあります。ただし、アプリ上で評価があっても、すべてのトラブルがなくなるわけではありません。

```quiz
Q: 仲介プラットフォームの価値は？
1: すべての部屋や車を必ず所有する
2: 相手探しや確認、料金・支払いなどの手間を減らす
3: 実際の安全確認を完全に不要にする
4: 貸した物が古くならなくなる
C: 2
E: 取引の手間を下げることで、以前は成立しにくかった貸し借りを支えます。安全や個人情報の問題は残ります。
```

## 3. みんなで作るソフトは、なぜ続く？

**オープンソース** は、中身の設計図に当たるソースコードを、ライセンスの条件に従って利用・変更・再配布できるソフトウェアです。

誰かが使っても、ほかの人が同じコードを使えます。一方、作ることや修正、運営には手間がかかります。「使う人が多いのに、誰が作るのか」という、公共財の供給に似た問いが出ます。

参加する動機は、親切心だけではありません。自分の問題を解く、腕を示す、学ぶ、仲間と楽しむなどが混ざります。

```quiz
Q: オープンソースへの参加動機について適切なのは？
1: 全員が直接の給料だけを目的にする
2: 親切心以外の理由は存在しない
3: 自分の利益になる動機と、他者を助ける動機が混ざる
4: コードを使うだけで修正費用もゼロになる
C: 3
E: 参加者や活動によって動機は違います。コードの複製が安くても、開発・保守の負担は残ります。
```

## 4. 企業は、無料で使える物になぜ協力する？

共有の土台がよくなると、企業の製品や保守サービスにも役立ちます。自社だけで全部作らず、ほかの参加者の改善も利用できます。

```flow
共有のソフトを改善する → 利用者や互換性が広がる → 関連サービスにも価値が生まれる
```

有料のソフトとの競争では、価格だけでなく、機能・対応・使い慣れ・移行の手間も重要です。無料なら、誰もがすぐ乗り換えるとは限りません。

```quiz
Q: 共有のソフトが安くても、すぐ普及するとは限らない理由は？
1: 利用者は費用を一切考えないから
2: 有料ソフトは法律で必ず優先されるから
3: オープンソースは改良できないから
4: 乗り換えの手間や、必要な機能・対応もあるから
C: 4
E: 価格の差だけでは決まりません。蓄積したデータや使い方、周辺ソフトとの関係も切替えの負担になります。
```

## 5. 自由に使えることと、ルールがないことは違う

| ライセンスの型 | 大まかな考え |
|---|---|
| MIT・BSDなど | 広い再利用を認め、表示などの条件を守る |
| GPLなど | 配布時に、対応するコードや同じ自由を守る条件がある |

> 補足：オープンソースは有料で販売することもできます。GPLも、あらゆる社内変更を常に世界へ公開せよという意味ではありません。配布の有無や版、使い方で条件が違うので、個別のライセンスを確認します。

ルールは、参加者が「協力しても、成果を一方的に閉じられないか」などを判断する材料です。開発を続けるためには、仕事の分け方や変更の決め方も必要です（共同の運営・ガバナンス）。

```quiz
Q: オープンソースなら、販売もルールもない？
1: 販売できる場合があり、利用・配布の条件は守る
2: 販売はどのライセンスでも必ず禁止
3: コードが見えれば条件を無視してよい
4: すべてのライセンスの条件は完全に同じ
C: 1
E: 無料という価格だけで定義されるものではありません。権利と条件を確かめることが、再利用と協力を支えます。
```

## 6. 共有を広げるときに、確かめること

| 見る点 | 問い |
|---|---|
| 技術 | 作業を分け、成果を確認できるか |
| 運営 | 誰が何を担当し、変更をどう決めるか |
| 動機 | 貢献が続く理由があるか |
| 社会のルール | 安全・働く条件・個人情報・税を守れるか |

```flow
新しい貸し借りが増える → 利用者の選択が広がる → 負担する人や安全も確かめる
```

新サービスで利用者が得をしても、既存の提供者の利益が減る場合があります。反対に、古い提供者を守るだけの規制は、便利な選択肢を妨げることもあります。安全と参入のしやすさを、両方見ます。

```quiz
Q: 共有サービスを評価するときに必要なのは？
1: 共有という名前なら安全確認は不要
2: 便利さだけでなく、安全や働く条件、競争も見る
3: 古い事業者の利益だけを守る
4: 新しい事業者には税のルールが適用されない
C: 2
E: 誰の利益が増え、誰が負担するかを分けます。技術だけでなく、運営と制度も共有を続ける条件です。
```

## 7. 持ち帰る考え

サイトやゲームを作るときにも、**すべて自分で所有・制作する必要があるか**を考えられます。共有できる土台と、守るべき条件を分けて見ます。
