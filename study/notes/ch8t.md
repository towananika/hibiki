# デジタル経済 8章【会話で読む】― ブロックチェーン

1節5〜10分。きょうは1節だけでOK。会話の3人は日替わり（アカリ・ツバサ・シオン）。詳しいノートは「[ふつうのノート](view.html?n=ch8)」。

## 1. 記録を信用できるか（5分）

```talk
B: ブロックチェーンって、何の問題を解くの？
A: 知らない相手とも取引するには、「誰が何を持つか」という記録を信用できることが大切。ゲームで持っている剣を、持ち主が自分で100本に書き換えられたら、売買は成り立たないよね。
B: ふつうは、どうしてる？
A: 運営会社や銀行などが記録を持つ。取引の記録帳を台帳という。
B: 問題は？
A: 人数や地域、確認の手順がふえるほど、記録を信用できるか確かめる費用が増える。
C: 信用できる記録が必要。
```

```card
要点
- 台帳：取引の記録帳
- 知らない相手との取引には、信用できる記録が必要
- 人数や地域がふえるほど、確かめる費用が増える
```

## 2. 記録を共有する（5分）

```talk
B: ブロックチェーンは、記録をどうする？
A: 1か所に任せず、複数の参加者で共有する（分散型台帳）。ブロックチェーンは、その一つ。
B: ブロックって？
A: 取引をまとめた「ブロック」を、前のブロックの情報とつなぐ。
B: 書き換えられない？
A: 記録の指紋のようなものがハッシュ値。内容から計算する値で、内容が変わると値も変わる。過去の記録を変えると、あとのつながりが合わなくなる。
B: ハッシュで本人もわかる？
A: ちがう。書いた本人の確認は、鍵を使う電子署名の役割。
C: ブロックをつなぐ。ハッシュ値で変更に気づく。
```

```card
要点
- 分散型台帳：複数の参加者が記録を保つ。ブロックチェーンはその一つ
- ブロック：取引のまとまり。前のブロックの情報とつながる
- ハッシュ値：記録の指紋。内容が変わると値も変わる
- 本人の確認は、電子署名の役割
```

## 3. どの記録を採用する？（5分）

```talk
B: 参加者の記録が食い違ったら？
A: どの更新を採用するか決める。合意の仕組み（合意メカニズム）という。
B: 方法は？
A: 作業証明（PoW）は、計算の作業を通して更新の候補を作る。計算資源や電力が必要。ビットコインはこれ。保有量などに基づく証明（PoS）は、資産を預けるなどの条件で検証に参加する。不正への罰則などの設計が大事。
B: 参加者はなぜ協力するの？
A: 協力する参加者への報酬（採掘・マイニング）が動機。仕組みを維持する動機 ＝ 参加の報酬と不正の負担。
C: PoW＝計算、PoS＝預けた資産。
```

```card
要点
- 合意メカニズム：食い違ったとき、どの更新を採用するか決める
- 作業証明（PoW）：計算の作業。電力が必要。ビットコイン
- PoS：資産を預けるなどで検証に参加。罰則の設計が重要
- 報酬が参加の動機（マイニング）
```

## 4. 参加の方式と、使いどころ（5分）

```talk
B: 誰でも参加できるの？
A: 方式が2つ。許可不要型は、不特定の人が参加するネットワーク。許可型は、決められた銀行どうしなどで記録を共有し、閲覧や更新の権限を決められる。
B: 分散していれば、全部公開される？
A: 公開するとは限らない。誰が読めて誰が更新できるかは、設計しだい。
B: いつでも使えばいい？
A: ふつうのデータベースのほうが簡単で安いなら、そちらを選ぶ理由がある。
C: 許可不要型と許可型。
```

```card
要点
- 許可不要型：不特定の人が参加。合意を保つ工夫が要る
- 許可型：決められた参加者。権限を決められる
- 分散している ≠ 全世界に公開
- ふつうのデータベースが安いなら、そちらを選ぶ
```

## 5. 記録と現実は別、スマートコントラクト（10分）

```talk
B: 記録できれば、正しいこと？
A: 別。食品の流通履歴を共有しても、最初に「農薬を使っていない」と入力した情報が正しいとは限らない。ブロックチェーンの外の情報を、どう正しく取り込むかが問題。
B: スマートコントラクトは？
A: あらかじめ決めた条件に従って動くプログラム。自動販売機のように、条件を満たしたら処理を実行する。
B: 弱点は？
A: 現実のあらゆる状況（配送中に壊れたら？）を書き切れるとは限らない。書いたコードに間違いがあれば、その通りに動いて困ることもある。
B: NFTは？
A: トークンを区別する仕組みで、著作権そのものを自動で保証するわけではない。
C: 記録できる ≠ 現実に正しい。
```

```card
要点
- 記録できること ≠ 現実に正しいこと（入力の正しさが問題）
- スマートコントラクト：決めた条件で自動実行するプログラム
- 弱点：現実のすべての状況は書き切れない。コードの間違いもそのまま動く
```

## 6. CBDC（中央銀行デジタル通貨）（5分）

```talk
B: 中央銀行のデジタル通貨（CBDC）は、ビットコインと同じ？
A: ちがう。CBDCは、その国の通貨単位で表され、中央銀行が直接の負債として発行する。ビットコインなどは、中央銀行が発行する通貨ではない。銀行預金は、基本的にその銀行に対する請求権。
B: ブロックチェーンが必須？
A: 必須とは限らない。
B: 期待と論点は？
A: 期待は、便利な決済と、銀行を使いにくい人への金融サービス。論点は、プライバシーと銀行への影響（預金がCBDCに移る）。
C: 「新技術だから使う」ではなく、「どの信頼の問題を、どれだけの費用で解くか」。
```

```card
要点
- CBDC：中央銀行が発行するデジタルのお金
- ビットコイン：中央銀行が発行する通貨ではない／銀行預金：その銀行への請求権
- CBDCにブロックチェーンが必須とは限らない
- 論点：プライバシー、銀行への影響
```
