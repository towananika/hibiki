# デジタル経済 8講 ― ブロックチェーン：記録を、どう信用する？

**知らない相手とも取引するには、「誰が何を持つか」という記録を信用できることが大切です。** ブロックチェーンは、その記録を共同で保つ仕組みの1つです。

添付の講義ノート第8章をもとにした教材です。ゲームの持ち物や、物の売買の例は、理解を助ける補足です。

## 1. ゲームの持ち物を、勝手に増やせたら？

ゲームで持っている剣を、持ち主が自分で100本に書き換えられたら、売買の約束は成り立ちません。

ふつうは、運営会社が記録を持ちます。「誰の物か」「代金を払ったか」を確かめてもらう方法です。銀行などの、信頼できる第三者に任せる方法も同じ発想です。

```flow
知らない相手と取引する → 持ち物や支払いを確認する → 信用できる記録が必要
```

取引の記録帳を **台帳（だいちょう）** といいます。人数や地域、確認の手順が増えるほど、記録を信用できるか確かめる費用も大きくなりえます。

```quiz
Q: デジタルの持ち物を取引するとき、重要なのは？
1: 記録を誰でも好きに書き換えられること
2: 持ち主や支払いの記録を信用できること
3: 必ず紙の証書を持つこと
4: 価格が絶対に変わらないこと
C: 2
E: 持ち物や支払いの記録を信用できなければ、二重に売られたかどうかも確かめにくくなります。信頼を作る仕組みが取引を支えます。
```

## 2. 1か所に任せず、記録を共有する

**分散型台帳** は、複数の参加者が記録を保ち、更新のルールに従って内容をそろえる仕組みです。ブロックチェーンは、その一種です。

取引をまとめた「ブロック」を、前のブロックの情報とつなぎます。

```flow
前の取引のまとまり → その情報を含む次のまとまり → さらに次のまとまり
```

記録の指紋のようなものが **ハッシュ値**。内容から計算する値で、内容が変わると値も変わります。過去の記録を変えると、その先のつながりにも影響するので、書き換えを見つけやすくなります。

> 補足：ハッシュだけで、書いた本人が誰かまで証明できるわけではありません。本人の鍵で確かめる「電子署名」とは役割が違います。また、記録を分散するだけでは不十分で、どの更新を認めるかというルールも必要です。

```quiz
Q: 過去のブロックの内容を書き換えると、どうなる？
1: 記録が自動的に正しい内容に戻る
2: 参加者全員の本人確認が不要になる
3: ハッシュ値や、その先のつながりに影響が出る
4: どんな方式でも絶対に書き換えが不可能になる
C: 3
E: 前のブロックの情報を次へつなぐため、変更の影響が後ろにも及びます。「変更を難しくする・発見しやすくする」仕組みであり、無条件に安全という意味ではありません。
```

## 3. どの記録を採用する？ ― 合意のルール

参加者の記録が食い違ったとき、どの更新を採用するか決めます。この仕組みを **合意の仕組み（合意メカニズム）** といいます。

| 方法 | 大まかな考え | 気をつけること |
|---|---|---|
| 作業証明（PoW） | 計算の作業を通して、更新の候補を作る | 計算資源や電力が必要 |
| 保有量などに基づく証明（PoS） | 資産を預けるなどの条件で、検証に参加する | 不正への罰則など制度の設計が重要 |

ビットコインはPoWを使います。更新に協力する参加者への報酬が、仕組みを支える動機になります（採掘・マイニング）。

```eq
仕組みを維持する動機 = 参加の報酬と不正の負担
```

> 補足：PoSの細かな選び方や罰則は方式ごとに違います。どの方式も、参加者が正直に動きやすい設計を考える必要があります。

```quiz
Q: 計算の作業を使うPoWで、報酬がある理由は？
1: 検証に資源を使う参加者が、協力する動機になるから
2: 報酬があれば、すべての入力情報が事実になるから
3: 報酬があれば、電力を一切使わなくなるから
4: 資産価格を必ず上げられるから
C: 1
E: 記録の維持には費用がかかります。その負担に見合う動機や、不正が割に合わない条件を設計することが経済学の論点です。
```

## 4. 誰でも参加する方式と、許可する方式

| 方式 | 例として考える場面 | 違い |
|---|---|---|
| 許可不要型 | 不特定の人が参加するネットワーク | 参加者を限定せず、合意を保つ工夫が要る |
| 許可型 | 決められた銀行どうしで記録を共有する | 閲覧・更新の権限を決められる |

**分散しているから、全情報を全世界に公開するとは限りません。** 誰が読めるか、誰が更新できるかは、仕組みの設計によります。

記録の共有が便利でも、管理や検証の費用はあります。ふつうのデータベースの方が簡単で安いなら、そちらを選ぶ理由があります。

```quiz
Q: 銀行など、決められた参加者だけで記録を更新したい場合に合うのは？
1: 全員の権限を区別できない仕組みだけ
2: 記録を一切保管しない仕組み
3: 自分だけが秘密の別台帳を持つこと
4: 閲覧や更新の権限を定めた許可型の仕組み
C: 4
E: 許可型では、参加者と権限を決められます。中央管理のデータベースで十分かどうかも含め、目的と費用で選びます。
```

## 5. 記録できることと、現実に正しいことは別

講義では、暗号資産だけでなく、所有権・物の流通履歴・本人情報などへの利用も扱います。

たとえば食品の流通履歴を共有すれば、どこを通ってきたか調べやすくなります。ただし、最初に「農薬を使っていない」とうそを入力した場合、その記録を改ざんしにくくしても、うそが事実になるわけではありません。

```flow
現実の出来事 → 正しく確認して入力する → 記録を共有して保つ
```

> 補足：ブロックチェーンの外の情報を、どう正しく取り込むかが問題です。NFTも、トークンを区別する仕組みであり、著作権などの権利が何でも自動で付くわけではありません。

```quiz
Q: 食品の履歴をブロックチェーンに載せれば、入力内容は必ず本当になる？
1: 必ず本当になる
2: 入力前の事実確認は、別に必要
3: 食品の品質は必ず向上する
4: 履歴を共有できなくなる
C: 2
E: 改ざんを見つけやすいことと、最初の入力が正しいことは別です。現実の検査や、入力する人の信頼性も必要です。
```

## 6. 条件を満たしたら、自動で実行する

**スマートコントラクト** は、あらかじめ決めた条件に従って動くプログラムです。自動販売機の「お金が入り、商品を選んだら出す」という例が、入口になります。

```flow
条件を決める → 条件が満たされたか確認する → 決めた処理を実行する
```

自動化で手間を減らせますが、「配送中に壊れたらどうする？」など、現実のあらゆる状況を書き切れるとは限りません。これを、契約の不完全性といいます。

書かれたコードに間違いがあれば、その通りに動いて困ることもあります。ブロックチェーンを使う必要があるかも、別に判断します。

```quiz
Q: スマートコントラクトでも残る問題は？
1: 決めた処理を一切自動化できない
2: すべての契約で必ず仲介者が増える
3: 想定しなかった状況や、コードの誤り
4: 条件を事前に決められない
C: 3
E: 決めた条件での実行を助けても、すべての状況を事前に書き切る問題や、入力・コードの誤りまでは自動的に解決しません。
```

## 7. 中央銀行のデジタル通貨は、ビットコインと同じ？

**中央銀行デジタル通貨（CBDC）** は、その国の通貨単位で表され、中央銀行の直接の負債として発行されるデジタルのお金です。

| 比べるもの | 大切な違い |
|---|---|
| CBDC | 中央銀行が発行する |
| ビットコインなど | 中央銀行が発行する通貨ではない |
| 銀行預金 | 基本的には、その銀行に対する請求権 |

一般の人や会社が使うものと、金融機関どうしの決済に使うものを分けて考えます。**CBDCに、ブロックチェーンが必須とは限りません。**

便利な決済や、銀行を使いにくい人への金融サービスが期待される一方、プライバシーや銀行への影響も論点です。預金からCBDCへ大きく移れば、銀行の貸出資金に影響しえます。保有上限や運営方法など、設計によって結果は違います。

```quiz
Q: CBDCについて、適切な説明は？
1: 中央銀行が発行し、ブロックチェーンは必須ではない
2: ビットコインの別名である
3: 必ず誰でも匿名で無制限に発行できる
4: 導入すれば銀行への影響を考えなくてよい
C: 1
E: 発行する主体と制度の設計が大切です。銀行預金や民間の暗号資産と区別し、便利さと金融システムへの影響を考えます。
```

## 8. 持ち帰る考え

**大切なのは、「新技術だから使う」ではなく、「どの信頼の問題を、どれだけの費用で解くか」です。** ゲーム内の持ち物でも、共同の記録が本当に必要かを先に考えられます。
